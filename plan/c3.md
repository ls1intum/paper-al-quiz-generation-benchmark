# C3 Plan: Learning Objective Alignment

## Goal

Implement a first-class per-item benchmark metric for C3, **Alignment with Learning Objective**, using the criterion numbering from `human-validation-plan.md`.

C3 asks: how directly does the item assess its stated learning objective?

Current status:
- The existing `coverage` metric is quiz-level and source-topic based.
- `coverage` does not score alignment against the per-item stated learning objective.
- Roadmap Task 2.3 explicitly says C3 is missing because `coverage` is only a source-topic proxy.
- The corpus contract already places the authoritative LO at `question.metadata.learning_objective`.

## Required Behavior

Add a question-level metric named `objective_alignment`.

The metric must:
- Produce one `MetricResult` per question with `question_id` populated.
- Use `question.metadata["learning_objective"]` as the primary reference value.
- Score whether the item directly assesses that stated LO, not whether it generally relates to the source material.
- Not invent an LO when the metadata field is absent or blank.
- Return a controlled non-applicable result for items without an LO.
- Keep the current `coverage` metric available for quiz/source-topic coverage, but do not treat it as C3.

Expected interpretation:
- High score: the item directly measures the stated LO at the relevant concept/skill level.
- Medium score: the item is related to the LO but tests only a prerequisite, surface vocabulary, or tangential concept.
- Low score: the item does not assess the stated LO.
- Non-applicable: no stated LO exists for the item.

Known corpus edge case:
- A few mapped items are deliberately blank because no catalogue entry covers them. They should remain ratable on other criteria and be explicit `applicable=false` for C3.

## Implementation Changes

Add `src/metrics/objective_alignment.py`.

Recommended structure:
- Class: `ObjectiveAlignmentMetric(BaseMetric)`
- `name`: `"objective_alignment"`
- `version`: `"1.0"`
- `scope`: `MetricScope.QUESTION_LEVEL`
- One LLM scoring phase is sufficient.

Suggested structured response schema:

```python
class ObjectiveAlignmentResponse(BaseModel):
    applicable: bool
    learning_objective: str | None
    alignment_level: Literal["direct", "partial", "weak", "none", "not_applicable"]
    matched_objective_aspects: list[str]
    missing_or_misaligned_aspects: list[str]
    rationale: str
    score: float = Field(ge=0, le=100)
```

Prompt requirements:
- Include question type, stem, options, marked answer, topic metadata if present, and the item-level `learning_objective`.
- Make clear that the LO is the denominator: source topics or quiz-level objectives are only context.
- Ask the model to identify which parts of the LO the item actually assesses.
- Ask it to distinguish direct assessment from loose topical relatedness.

Missing-LO behavior:
- If `question.metadata.get("learning_objective")` is absent, blank, or only whitespace, do not call the LLM.
- Return a deterministic response with:
  - `applicable=false`
  - `alignment_level="not_applicable"`
  - `score=100` or another documented neutral value.
- Prefer `score=100` for compatibility with existing score range semantics, but ensure `raw_response` and metadata clearly mark `applicable=false` so analysis can filter these items out.

Register the metric in:
- `src/metrics/__init__.py`
- `main.py`
- data-collection benchmark config.

Do not add `learning_objective` to `QuizInstructions` for this task. The validation corpus already stores C3’s item reference in question metadata, and Form A pools mix items from different LOs.

## Tests

Add focused tests in `tests/test_metrics.py`:
- Prompt builder requires `question`.
- Prompt includes `question.metadata.learning_objective`.
- Missing LO returns a valid non-applicable result without using the LLM.
- Parse accepts valid scores and rejects invalid scores.
- Mock response for direct alignment produces the expected score.
- Mock response for weak alignment preserves `alignment_level` in `raw_response`.

Add runner/registry tests:
- Metric is registered by `register_metrics()`.
- A quiz with N questions produces N `objective_alignment` results.
- Items with missing LO still produce results and do not abort the run.

## Documentation

Update:
- `docs/docs/user-manual/metrics.md`: document `objective_alignment`, item-level scope, metadata dependency, and non-applicable behavior.
- `CRITERIA_COVERAGE_REPORT.md`: state that C3 is covered by `objective_alignment`; retain `coverage` as source-topic/quiz coverage only.
- Contributor docs if they currently imply that `coverage` is the LO-alignment implementation.

## Acceptance Criteria

- `MetricRegistry.list_metrics()` includes `objective_alignment`.
- Every item with `metadata.learning_objective` receives a per-item C3 score.
- Items without an LO produce explicit `applicable=false` output and are filterable during analysis.
- Benchmark output can join C3 scores by `(quiz_id, question_id)`.
