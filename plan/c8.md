# C8 Plan: Absence of Cueing

## Goal

Implement a first-class per-item benchmark metric for C8, **Absence of Cueing**, using the criterion numbering from `human-validation-plan.md`.

C8 asks: does the item avoid grammatical, semantic, or structural clues that reveal the correct answer?

Current status:
- No dedicated cueing metric exists.
- `distractor_quality` contains only incidental hint-related checks.
- `homogeneous_options` can detect some structural outliers, but it is C7, not C8.
- Roadmap Task 2.3 requires missing per-item judge scores for C8 before analysis.

## Required Behavior

Add a question-level metric named `absence_of_cueing`.

The metric must:
- Produce one `MetricResult` per question with `question_id` populated.
- Treat high scores as better absence of cueing.
- Detect cueing that lets a respondent identify the key without content mastery.
- Return binary cue presence plus severity.
- Preserve machine-readable cue types in `raw_response`.
- Not require `source_text`.

Cue types to cover:
- `grammatical`: article agreement, singular/plural agreement, stem-option grammar revealing only the key.
- `length`: the keyed option is conspicuously longer, shorter, or more qualified.
- `semantic`: stem wording or distinctive terms repeat only in the key.
- `convergence`: the key combines elements repeated across distractors or is logically implied by option overlap.
- `specificity`: the key is uniquely detailed, hedged, or technically precise.
- `other`: any other clue pattern with rationale.

Severity values:
- `none`: no cue.
- `minor`: cue may help but does not make the key obvious.
- `strong`: cue likely reveals the key.

The validation plan’s primary analysis is binary cue present/absent. Severity is retained for optional three-level analysis if pilot agreement supports it.

## Implementation Changes

Add `src/metrics/absence_of_cueing.py`.

Recommended structure:
- Class: `AbsenceOfCueingMetric(BaseMetric)`
- `name`: `"absence_of_cueing"`
- `version`: `"1.0"`
- `scope`: `MetricScope.QUESTION_LEVEL`
- A deterministic pre-analysis helper for length cueing plus one structured LLM scoring phase.

Suggested structured response schema:

```python
class CueingResponse(BaseModel):
    cue_present: bool
    severity: Literal["none", "minor", "strong"]
    cue_types: list[str]
    key_revealed_by: list[str]
    deterministic_length_signal: dict[str, Any]
    rationale: str
    score: float = Field(ge=0, le=100)
```

Deterministic length signal:
- Calculate character or token lengths for all options.
- Identify whether the marked key is a clear outlier.
- Use a conservative threshold, for example keyed option length is at least 1.5x the median distractor length and differs by at least 20 characters.
- Include the signal in the prompt and raw response, but let the LLM decide final severity.

Prompt requirements:
- Include stem, all options, marked key, question type, and deterministic length analysis.
- Ask the evaluator to ignore factual correctness and focus only on clues.
- Compare stem-to-key, key-to-distractors, and option-set patterns.
- Explicitly separate C8 cueing from C7 homogeneity: grammatical cueing may also be non-homogeneity, but C8 is about whether the key is revealed.

Register the metric in:
- `src/metrics/__init__.py`
- `main.py`
- data-collection benchmark config.

## Tests

Add focused tests in `tests/test_metrics.py`:
- Prompt builder requires `question`.
- Prompt includes all options and the marked key.
- Deterministic length helper flags a clear keyed length outlier.
- Deterministic length helper does not flag small normal differences.
- Parse validates score range and severity.
- Mock response with no cue produces high score and `cue_present=false`.
- Mock response with length cue preserves `cue_types=["length"]`.

Add runner/registry tests:
- Metric is registered by `register_metrics()`.
- A quiz with N questions produces N `absence_of_cueing` results.
