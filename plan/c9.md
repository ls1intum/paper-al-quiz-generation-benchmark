# C9 Plan: Grammatical Correctness Per-Item Scores

## Goal

Expose per-item benchmark scores for C9, **Grammatical Correctness**, using the criterion numbering from `human-validation-plan.md`.

C9 asks: are the stem and options grammatically correct and properly punctuated?

Current status:
- `GrammaticalCorrectnessMetric` exists in `src/metrics/grammatic.py`.
- It is currently `MetricScope.QUIZ_LEVEL`.
- Roadmap Task 2.3 requires C9 per-item judge scores.
- `CRITERIA_COVERAGE_REPORT.md` already notes that quiz-level grammar can mask one broken item among many clean items.

## Required Behavior

Convert grammar scoring to per-item output.

The final benchmark artifacts must:
- Contain one `grammatical_correctness` result per question.
- Populate `question_id`.
- Score the stem and all options for that item.
- Preserve the existing language-instruction adjustment behavior where applicable.
- Keep high scores as better grammar.

The metric should evaluate:
- grammar
- spelling
- punctuation
- capitalization
- sentence structure
- technical-writing correctness
- consistency of terminology where it affects grammar/readability

## Implementation Changes

Preferred approach: convert `GrammaticalCorrectnessMetric` to question-level.

Changes in `src/metrics/grammatic.py`:
- Change `scope` from `MetricScope.QUIZ_LEVEL` to `MetricScope.QUESTION_LEVEL`.
- Update `_build_score_prompt` to require `inp.question`, not `inp.quiz`.
- Format one question, its options, and marked answer.
- Keep the `language` parameter.
- Keep `BaseMetric` instruction adjustment coupled to `grammatical_correctness`.

Recommended structured response:
- Replace the current generic `ScoreResponse` with a grammar-specific schema if practical:

```python
class GrammaticalCorrectnessResponse(BaseModel):
    grammar_issues: list[str]
    spelling_issues: list[str]
    punctuation_issues: list[str]
    severity: Literal["none", "minor", "major", "critical"]
    rationale: str
    score: float = Field(ge=0, le=100)
```

If keeping `ScoreResponse`, at minimum ensure docs note that only numeric score is returned. Prefer the structured schema because validation analysis and debugging benefit from issue categories.

Optional aggregate:
- If existing reports need a quiz-level grammar summary, add it in reporting/aggregation from per-item rows.
- Do not keep quiz-level-only C9 as the validation output.

## Tests

Update existing grammar tests and add new ones:
- Prompt builder now raises when `question` is missing.
- Prompt builder includes the question stem, options, and marked answer.
- Runner emits N `grammatical_correctness` results for a quiz with N questions.
- Each grammar result has non-null `question_id`.
- Language instruction adjustment still applies only to `grammatical_correctness`.
- Parse validates score range.

Update any tests that assumed grammar was quiz-level.

## Acceptance Criteria

- Benchmark output contains one C9 score per item.
- No C9 result required by validation has `question_id=None`.
- Existing benchmark summaries still aggregate grammar rows sensibly.
- Language mismatch remains handled as an instruction compliance adjustment, not as grammar quality itself.
