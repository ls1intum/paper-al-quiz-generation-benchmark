# C2 Plan: Answer-Key Correctness

## Goal

Implement a first-class per-item benchmark metric for C2, **Answer-Key Correctness**, using the criterion numbering from `human-validation-plan.md`.

C2 asks: is the marked answer key correct and unambiguous?

Current status:
- No dedicated metric exists in this repository.
- `accuracy` checks factual correctness of the item and marked answer, but it does not verify whether distractors are also defensibly correct.
- `clarity` mentions a single correct answer only incidentally.
- Roadmap Task 2.3 requires missing per-item judge scores for C2 before analysis.

## Required Behavior

Add a question-level metric named `answer_key_correctness`.

The metric must:
- Produce one `MetricResult` per question with `question_id` populated.
- Work for `single_choice`, `multiple_choice`, and `true_false`.
- Treat high scores as better answer-key correctness.
- Not require `source_text`; use source material when available, but fall back to domain/expert reasoning when absent.
- Return structured diagnostics in `raw_response`, not only a score.

Question-type rules:
- `single_choice`: exactly one option is unambiguously correct, and it is the marked `correct_answer`.
- `true_false`: exactly one of `True`/`False` is unambiguously correct, and it is the marked `correct_answer`.
- `multiple_choice`: the marked answer set must equal the full unambiguously-correct set; every keyed option must be correct and no unkeyed option may also be defensible.

Issue flags to expose:
- `multiple_defensible`: at least one unkeyed option is also defensibly correct.
- `keyed_answer_wrong`: at least one keyed option is incorrect.
- `no_correct_option`: no option is defensibly correct.
- `catch_all_present`: an all/none-of-the-above style option is present.
- `ambiguous_key`: correctness cannot be decided unambiguously from item wording and available context.

Known corpus edge case:
- `1819ER_q3` has `correct_answer = []`. The benchmark must not crash. It should produce a valid C2 result and flag the item as failing key correctness, usually via `no_correct_option` or `ambiguous_key`.

## Implementation Changes

Add `src/metrics/answer_key_correctness.py`.

Recommended structure:
- Class: `AnswerKeyCorrectnessMetric(BaseMetric)`
- `name`: `"answer_key_correctness"`
- `version`: `"1.0"`
- `scope`: `MetricScope.QUESTION_LEVEL`
- One deterministic precheck phase, one LLM scoring phase, or a single scoring phase with deterministic helpers called from the prompt builder.

Suggested structured response schema:

```python
class AnswerKeyCorrectnessResponse(BaseModel):
    key_correct: bool
    defensible_correct_options: list[str]
    issue_flags: list[str]
    catch_all_options: list[str]
    rationale: str
    score: float = Field(ge=0, le=100)
```

Add deterministic catch-all detection before the LLM call:
- English examples: `all of the above`, `none of the above`, `all answers`, `none of these`, `all listed`, `no answer is correct`.
- German examples: `alle genannten`, `alle antworten`, `keine der genannten`, `keine antwort`, `nichts davon`, `alle oben genannten`.
- Normalize case and whitespace; keep matching conservative to avoid overflagging normal domain text.

Prompt requirements:
- Include question type, stem, every option, and marked key.
- Explicitly ask the evaluator to identify the full defensibly-correct option set before judging the marked key.
- For MC, compare sets, not individual labels.
- Ask for issue flags using the exact machine-readable names above.
- Mention that catch-all options are a C2 violation even when technically correct.
- If `source_text` is present, present it as supporting context. If absent, state that the judge should use general expert knowledge and the item wording.

Register the metric in:
- `src/metrics/__init__.py`
- `main.py`
- any benchmark config intended for the data-collection run.

Do not change the public quiz schema. Use existing `QuizQuestion.correct_answer`, `options`, `question_type`, and optional metadata.

## Tests

Add focused tests in `tests/test_metrics.py`:
- Prompt builder requires `question`.
- Prompt includes all options and the marked key.
- `parse_score` accepts valid scores and rejects scores outside 0-100.
- Deterministic catch-all detection covers English and German examples.
- `single_choice` mock response with one correct keyed option passes.
- `multiple_choice` mock response with an omitted correct option flags `multiple_defensible`.
- Wrong keyed option flags `keyed_answer_wrong`.
- Empty MC key does not crash.

Add runner/registry tests:
- Metric is registered by `register_metrics()`.
- A quiz with N questions produces N `answer_key_correctness` results.
- Each result has `metric_name == "answer_key_correctness"` and non-null `question_id`.

## Documentation

Update:
- `docs/docs/user-manual/metrics.md`: add the implemented metric name, scope, behavior, and issue flags.
- `CRITERIA_COVERAGE_REPORT.md`: change C2 from missing to covered by `answer_key_correctness`, noting that source-free judging is supported.
- Any example benchmark config used for validation to include `answer_key_correctness`.

## Acceptance Criteria

- `MetricRegistry.list_metrics()` includes `answer_key_correctness`.
- Benchmark output contains one C2 score per item.
- `raw_response` includes `key_correct`, `defensible_correct_options`, `issue_flags`, and `rationale`.
- Catch-all options are flagged deterministically.
- The known empty-key item can be evaluated without aborting the benchmark.
